## Addendum: GUI smoke test on an isolated scratch copy (2026-10-23)
Method (be exact): a 2.8 GB scratch copy of the app (no .git, no node_modules), the amended patch applied THERE, the app run in a live Tk event loop from that folder with its own `settings.json` (`projects_root` pointing at a scratch folder; in dev mode the app keeps settings next to `app.py`, so the real settings were never read or written) and one scratch project (the Korea script and a macOS `say` voiceover). The REAL widgets were driven through their own commands (`switch.toggle()`, `button.invoke()`) by `driver_smoke.py`, which also read widget state; modal message boxes were replaced by recorders (nobody could click them); **no pixels were captured** (no screen-recording permission, and the Python process has no bundle id for computer control). Logs: `phase8_evidence/gui_smoke/`.
Seen: switch default OFF, button disabled and visible; "Write plan with AI", "Load beat CSV" normal; direct() while off does nothing; switching ON enables the button and writes `explainer_style: true` to the scratch settings; Direct: button "Directing…" disabled, progress card "Directing the Explainer look", plan installed after 28.5 s (10 beats: 9 footage + 1 map), button restored, status "Explainer plan ready: 10 beats…"; forced failure (voiceover replaced by 2 KB of random bytes): the real error text, plan object unchanged, button restored, progress card closed; Stop during a run (clips re-encoding): button restored at once, plan unchanged, the late answer ignored (no dialog, no change); restart: switch restored ON, plan restored (10 beats); switching OFF persisted `false`.
Not covered: mouse clicks and pixels, the Visual Plan table (0 rows: the Explainer's clips are local files, so there is nothing to fetch), Generate scenes / Render from the GUI, other styles, Windows.
