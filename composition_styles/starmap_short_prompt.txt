Write the StarMap BEAT PLAN CSV for this space documentary script (Semantic YT Studio).
(The short prompt: for a story that names no built-in mission. The app gives the full prompt when it does.)

OUTPUT: only the CSV, starting with the header. No explanations, no code fences, no blank lines.
Quote every cell that contains a comma. Use plain ASCII quotes.

HEADER (exactly):
beat,row,vo_anchor,mode,type,id,place,frame,date,label,sub,text,value_from,value_to,format,anchor,until,hold,asset,dur,why,extra

ROW 1 (plan row): beat=plan, row=plan, date=today as YYYY-MM-DD if the script talks about the present
(else empty), label=THE VIDEO TITLE IN CAPITALS. All other cells empty.

BEATS (b1, b2, b3 ... in order). Each beat starts with a row=beat line, then its own layer/card/clip rows.
- text: the beat's narration copied EXACTLY from the script, whole sentences. All beat texts joined
  together must equal the script word for word (nothing skipped, changed or repeated).
- vo_anchor: the first 3-5 words of that beat's text, copied exactly; add words until it is unique in the script.
- mode: map (3D space map), map_footage (map + 1-3 photo cards), or footage (1-3 full-screen clips).
- place (map beats): one of these bodies:
               <<<BODIES>>>
  or a pair such as earth+moon or jupiter+europa. If the story is about a moon, place = that moon
  (europa), not its planet.
- frame (map beats): close, body, system (body with its moon), inner, solar, galaxy, universe.
- why: a short phrase saying what the beat does. type, id, date: leave empty.
- extra: empty, or {"context": "europa"} when a wider view of the planet is deliberate while the moon is
  named, or {"hold": true} when a still repeated view is deliberate.

UNDER A BEAT (vo_anchor = 2-5 words copied from THAT beat's own text):
- row=layer (map / map_footage only), type one of:
    title   -> label (title in capitals), sub optional. Once per video part.
    caption -> text, at most 44 characters.
    stat    -> value_to = the number the narrator says, format with a placeholder and unit
               ("#,##0 KM", "0.0 KM/S", "0 YEARS"; never type the number in format), sub = small caption,
               anchor = bl, br or tl.
    pointer -> place = a body, label = its name in capitals.
    line    -> id = measure, place = two bodies separated by ; (earth;jupiter), label = what it says.
- row=card (map_footage only, 1-3): asset = nasa_image:<specific description> or stock_image:<...>,
  label = SHORT NAME IN CAPITALS, anchor = tr, ml, mr or bl (different for cards shown together).
- row=clip (footage only, 1-3): asset = nasa_video:<real NASA mission footage>, nasa_image:<...>,
  stock_video:<...> or stock_image:<...>; why = what it shows.

RHYTHM AND CAMERA
- Map for where / how far / scale; footage for what something looks like up close. Footage about
  25-45% of the time. A footage beat 5-12 s, a map beat 8-20 s (about 2.5 spoken words per second).
- Something new on the map at least every 5 s (a card, caption, stat, pointer or line).
- Never more than 2-3 map beats in a row with the same place and frame: move between views
  (system -> body -> close) or places, or cut to footage. Go planet system -> moon -> moon close,
  not moon to moon directly.
- Each number the narrator says gets a stat. Don't put two stats in the same corner at once.
- Describe pictures concretely ("Galileo close-up of Europa's cracked icy surface"), never file names,
  never the same description twice. Use stock_video for space scenery; nasa_video only for real missions.
- Show only what the script says. Do not invent facts, numbers or dates. Do not use spacecraft,
  path, orbit or mission event rows (craft/path/orbit layers, qualified dates) unless the script is about
  a built-in mission.
